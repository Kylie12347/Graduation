# RFID单品标签仿真说明

RFID用于识别单件商品，SKU用于区分商品规格。同一SKU的两瓶可乐分别绑定不同EPC。编号采用EPC前缀加32位UUID十六进制串，是虚拟唯一标识，不宣称符合实际硬件EPC编码标准。

## 数据与流程

新增rfid_items表：epc主键、cabinet_id柜体、product_id商品SKU、location位置（IN_CABINET/OUTSIDE）、held_session取出它的会话。rfid_initialized记录柜体是否已迁移。

1. 第一次查看标签、仿真操作或补货时，在柜体行锁内为原库存分配唯一标签；已有未结束会话的柜外商品也迁移。历史已支付商品不倒推补建标签，原订单和库存不重置。
2. 取出前扫描柜内标签，形成beforeTags；移动对应数量的虚拟单品到柜外，并记住会话；再次扫描得到afterTags。
3. 消失标签=beforeTags减afterTags，代表取出；新增标签=afterTags减beforeTags，代表放回。读卡列表先去重，再按标签登记表tagProducts聚合到SKU及带符号数量。
4. Signal保留rfidDelta便于展示，但新事件的FusionEngine会从rfid快照重新计算，不信任该缓存。融合器依次检查重量、RFID、视觉，不读取库存、位置或simulation_actions。
5. 放回时选择该会话持有的同SKU标签，恢复相同EPC，不重新创建。面板仍按SKU及数量操作，相同SKU多件时按EPC排序选择，不提供人工指定某个EPC的交互。
6. 补货每增加一件，就创建一个新标签。已支付商品保留柜外标签与会话关联以便追溯；销量仍由订单结算维护，不凭标签数推算已售金额。

## 异常

RFID漏读：在beforeTags和afterTags两个观测窗口均隐藏本次变化的标签，模拟无法观测该变化；真实位置仍会改变。该模式不是随机百分比漏读，也不会声称覆盖所有射频干扰模型。

错误映射：仅修改本事件观测中的tagProducts，模拟标签登记或解码错误。真实标签库的SKU绑定不受影响。漏读与错误映射同时勾选时，漏读优先。

视觉仍只提供有差异/无差异。重量候选唯一、RFID缺失且视觉无差异时沿用原规则允许确认；等重商品漏读、重量与RFID冲突、视觉有差异时待人工确认。

## 接口和界面

管理员GET /api/admin/rfid-items?cabinetId=CAB001返回该柜体单品标签和位置。消费者无法调用管理接口。管理端虚拟售货柜新增标签表；每个融合事件的观测JSON包含前后标签列表、观测绑定表及汇总变化。小程序原接口保持兼容，不需要重新设计消费者购买流程。

旧事件没有rfid字段时，仍可按原来的rfidDelta读取，保留历史记录。旧库存只有SKU数量，因此迁移时创建新标签，无法恢复过去从未记录的单品身份。
