# 小程序消费者页面改版说明

## 消费者操作

首页展示某台柜体的在售商品、示意图片、价格和实际柜内余量，售罄商品明确标注。没有扫码时只是商品预览，不显示柜号输入框，也不能从附近列表直接开门。

点击“扫码开柜”扫描柜体二维码，二维码里的柜号唯一决定开哪台柜。支持二维码内容CAB001、包含cabinetId=CAB001的URL，以及小程序码scene=CAB001或scene=cabinetId%3DCAB001。二维码不接受金额和购买清单。先验证柜体存在，再请求原开柜接口。

从外部小程序码直接进入首页时，页面绑定已验证柜体，展示“开启这台售货柜”，无需再次选柜。未完成购物优先展示“继续购物/结算”。开发者工具可添加首页启动参数cabinetId=CAB001进行演示；这只是开发入口，不提供消费者手动输入柜号。

购物清单只展示已确认商品、数量、小计和待确认项目；不向消费者呈现重量、RFID、视觉步骤、融合原因、EPC或内部会话编号。融合证据仍完整保存在后端及管理界面，算法和订单计算规则保持原有流程。

需要人工确认时，点击“去选择”进入独立resolve页面。点击商品卡片选择商品，用“拿走了/放回了”和数量加减按钮完成核对，无picker滚轮、无弹层、无需填写技术说明。首次进入不默认勾选商品，必须明确点击后才能确认。后端仍记录自动生成的人工确认说明。保存后返回清单并刷新；已核对项目在清单最终确认前允许修改。

附近售货柜页展示已配置柜体的位置、可用状态，并可浏览其货架；浏览不会改变扫码绑定的柜体。当前柜体只有位置文字，因此这一版是配置位置列表，不声称已实现GPS附近搜索、距离排序或导航。所有商品图片是程序绘制的包装示意图；新SKU自动使用通用包装图。

## 文件

新增页面：pages/resolve、pages/nearby。重写home、shopping页面。utils/storefront.js统一二维码解析与本地图片映射。

新增GET /api/cabinets/{id}/catalog，由StorefrontService返回消费者可见的本柜在售商品与库存；不开放运营统计和传感器数据。没有数据库结构变更。

assets/products包含可乐、水、茶、果汁、饼干与通用包装PNG。scripts/generate-product-assets.cjs可重建资源，纯Node标准库实现。

## 验证与验收

实际执行19项后端规则及Spring MockMvc/H2集成测试，19通过0失败；新增本柜商品目录隔离、价格库存、占用状态、鉴权用例。小程序逻辑测试9组全部通过，涵盖二维码格式、预览不可开柜、扫码唯一柜绑定、启动参数、清单隐藏融合日志、选择与提交、结算后禁止修改、附近浏览隔离及本地资源。JS/JSON与5页事件绑定检查通过，5页WXML使用微信开发者工具内置wcc编译通过。

受当前执行环境路径权限限制，Java通过javac生成类文件后使用Spring TestContext运行测试；关闭依赖JAR时仍有AccessDeniedException诊断，不宣称Maven verify已成功。未完成开发者工具中点击全流程、真机扫描或浏览器视觉回归。

验收时重启IDEA后端，重新编译小程序；先查看首页图片价格，再用cabinetId=CAB001启动参数或二维码开柜。管理台制造RFID冲突/漏读，关柜后核对“需要你确认”是否只列商品，点击进入独立页，选择并保存，回到清单完成模拟支付。管理台仍可查看三步融合过程。
