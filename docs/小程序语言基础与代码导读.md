# 小程序语言基础与代码导读

## 1. 一个页面的四个文件

| 文件 | 作用 | 本项目示例 |
|---|---|---|
| `.wxml` | 描述页面结构，相当于模板 | 商品清单、按钮、状态标签 |
| `.wxss` | 定义页面样式，类似CSS | 颜色、卡片、rpx尺寸 |
| `.js` | 数据与交互逻辑 | 开柜、请求接口、支付 |
| `.json` | 页面配置 | 导航标题、下拉刷新 |

`app.json`注册页面和底部Tab栏；`app.js`通过`App()`注册整个程序；`app.wxss`存公用样式。`project.config.json`是开发者工具配置，不是业务数据库。

## 2. WXML数据绑定

```xml
<view>{{cabinetId}}</view>
<button bindtap="open">申请开柜</button>
<view wx:if="{{active}}">有未完成购物</view>
<view wx:for="{{cabinets}}" wx:key="id">{{item.name}}</view>
```

`{{}}`读取页面data；`wx:if`控制节点是否存在；`wx:for`循环数组；`wx:key`提供稳定标识，帮助框架正确更新列表。`view`用于布局，`text`显示文字，`input`收集输入，`picker`提供选择器。

`bindtap="open"`将点击绑定到JS的`open()`方法。循环中`data-id="{{item.id}}"`把编号附在节点上，处理函数通过`e.currentTarget.dataset.id`取得。输入框的新值使用`e.detail.value`。

## 3. JavaScript与响应式更新

```javascript
Page({
  data: { cabinetId: 'CAB001', loading: false },
  inputCabinet(e) {
    this.setData({ cabinetId: e.detail.value });
  }
});
```

`Page()`注册页面。`data`不是普通界面HTML，而是模板的数据源。`this.setData()`会同步更新模板；仅执行`this.data.loading=true`不会可靠刷新界面。

`const`声明不重新赋值的变量；`let`声明可重新赋值的变量。对象属性仍可以改变。`map`用于把接口数组转为显示数组，`find`查找一个元素，`filter`筛选多个元素，`reduce`累计金额。`===`同时比较类型和值，应优先于宽松比较`==`。

本项目中的`{ ...item, amount: money(item.total_cents) }`使用对象展开语法创建新对象，保留原字段并补充显示金额。`${id}`属于JS模板字符串语法，外侧使用反引号；WXML里的`{{}}`是另一套模板语法，二者不要混淆。

## 4. 异步接口

```javascript
try {
  const result = await request('/sessions', 'POST', { cabinetId: 'CAB001' });
  wx.navigateTo({ url: '/pages/shopping/shopping?id=' + result.id });
} catch (error) {
  message(error);
}
```

网络请求需要等待，`await`暂停当前异步函数，直到Promise完成，不阻塞整个手机界面。`try/catch`捕获业务错误与网络错误。`finally`常用于恢复loading状态，无论成功失败都会执行。

`utils/api.js`用Promise封装`wx.request`。小程序没有普通浏览器DOM，不能用`document.querySelector`操作视图，也不应直接照搬网页fetch代码。API地址统一从`getApp().globalData.baseUrl`读取，方便切换模拟器和真机环境。

HTTP请求携带`Authorization: Bearer <token>`。消费者令牌与管理员令牌分离，消费者不能直接调用后台取放、补货接口。令牌来自本地匿名演示登录，不是微信官方登录凭证。

## 5. 生命周期

- `onLoad(options)`：创建页面时执行，读取路由参数id。
- `onShow()`：页面每次显示时执行，刷新数据，启动轮询。
- `onHide()`：页面被其他页覆盖时执行，清理定时器。
- `onUnload()`：页面销毁时执行，再次确保定时器已清理。
- `onPullDownRefresh()`：下拉刷新，结束后调用`wx.stopPullDownRefresh()`。

购物页每2.5秒查询一次会话。`fetching`防止网络慢时叠加请求；`visible`避免已经离开页面后再setData。真实项目可进一步改用WebSocket，本项目轮询已能演示联动。

## 6. WXSS与布局

`rpx`是自适应尺寸：微信将屏幕宽度换算为750rpx。常见手机上`32rpx`通常约为16px，但不要把二者固定等同。`display:flex`实现左右布局，`border-radius`实现圆角，`padding`控制内部留白，`margin`控制外部间距。

全局公用类在`app.wxss`定义，例如`.card`、`.primary`。页面自己的`.wxss`只存局部样式，减少重复。

## 7. 阅读代码顺序

先读`app.json`了解路由，再读`utils/api.js`了解请求封装，然后按`home → nearby → shopping → resolve → orders`阅读。对每个页面，先看WXML的按钮绑定，再到JS中寻找同名方法，最后到后端`ApiController`寻找对应路径。

异常核实在独立的`resolve`页面中完成：点击商品卡片，点击“拿走了/放回了”切换方向，用加减按钮修改数量；不使用picker滚轮或弹层。首页商品卡只展示图片、价格和柜内余量，不提供加入购物车。正常购物仍由仿真面板产生取放事件。

扫码解析集中在`utils/storefront.js`。`app.js`接收小程序码启动参数；`home.js`验证二维码中的柜号后绑定唯一柜体。附近页面只设置预览柜号，不改变扫码绑定柜号；这样浏览其他柜体商品时不会误开柜。商品示意图在`assets/products`，可运行`node scripts/generate-product-assets.cjs`重建。
